# Module Design

## Purpose

This document defines the functional modules of the Technology Governance Assessment and Prioritization process. The modules translate the overall process architecture into specific functions, inputs, methodologies, and outputs.

The design is process-oriented and does not assume that the final solution must be implemented as a conventional software application.

## Module 1: Existing Practice Identification

### Input

- Organization's existing technology governance practices
- Existing informal governance practices, where applicable

### Methodology

Document the technology governance practices currently used by the organization. The purpose is to establish the organization's starting point before introducing additional practices identified through the literature.

### Output

- Documented list of existing technology governance practices

## Module 2: Practice Comparison

### Input

- Organization's existing practice list
- Technology governance practices identified from the eight core literature sources

### Methodology

Compare the organization's existing practices with the literature-based practices. Identify practices that are already represented in the organization and literature-based practices that are not currently represented.

### Output

- Practices already represented in the organization
- Literature-based practices requiring further assessment

## Module 3: Organizational-Factor Assessment

### Input

- Practices being considered
- Organizational factors
- Organizational weights or point values

### Methodology

Assess each practice against organizational factors to determine its relevance to the organization's circumstances. The assessment considers factors such as the organization's ability to remain in operation, mission and vision, goals and objectives, customers, resources and capabilities, technology orientation, current governance, and external environment.

### Output

- Completed assessment results
- Practice scores

## Module 4: Scoring and Priority Ranking

### Input

- Assessment results
- Organizational scoring criteria
- Priority thresholds

### Methodology

Apply the organization's scoring approach to the assessment results. The resulting score is used to assign a priority category according to thresholds established by the organization.

### Output

- Practice scores
- Priority rankings

## Module 5: Practice Selection and Feasibility

### Input

- Existing organizational practices
- Assessed literature-based practices
- Priority results
- Organizational resources and constraints

### Methodology

Literature-based practices that are appropriate for the organization are added to the organization's existing practice list based on their assessment and priority results.

The resulting practice list is then assessed for implementation feasibility. Feasibility may consider funding and budget, staffing, expertise, technology and infrastructure, time, and other relevant organizational resources and constraints.

When a practice is determined to be not currently implementable, it is deprioritized for current implementation. The reason for deprioritization is documented and the practice is moved to the assessment record for traceability.

### Output

- Organization-specific practice list
- Feasibility decisions
- Deprioritized practices with documented reasons

## Module 6: Assessment Record and Traceability

### Input

- Assessment results
- Scores
- Priority decisions
- Feasibility findings
- Inclusion, exclusion, and deprioritization decisions
- Reasons and supporting notes

### Methodology

Maintain a record of the assessment and decision-making process. The record preserves the reasoning behind practice selection, prioritization, feasibility decisions, and deprioritization.

### Output

- Traceable assessment record
- Documented decision history

## Module 7: Implementation Roadmap

### Input

- Feasible practices remaining after assessment and feasibility decisions

### Methodology

Arrange feasible practices according to implementation order. The roadmap provides a concise description of what the organization needs to do for each practice.

### Output

The implementation roadmap contains:

| Rank | Practice | Description |
|------|----------|-------------|
| 1 | Practice A | What the organization needs to do |
| 2 | Practice B | What the organization needs to do |

Implementation, evaluation, and reassessment are separate activities and are not included as roadmap columns.

## Module 8: Implementation

### Input

- Implementation roadmap
- Organizational resources and capabilities

### Methodology

Implement the selected technology governance practices according to the established roadmap.

### Output

- Implemented governance practices
- Implementation experience and observations

## Module 9: Evaluation

### Input

- Implemented practices
- Implementation experience
- Organizational observations

### Methodology

Evaluate each implemented practice by determining:

1. Whether the practice was implemented
2. What issues occurred
3. Why the issues occurred
4. Whether additional organizational support could have helped
5. What improvements are needed

### Output

- Evaluation findings
- Identified implementation issues
- Identified causes
- Improvement needs

## Module 10: Reassessment and Adaptation

### Input

- Previous assessment record
- Implementation roadmap
- Evaluation findings
- Changes in organizational circumstances

### Methodology

Reassess the organization's technology governance practices when appropriate or when significant circumstances change. The previous assessment record and roadmap provide the starting point for determining what has changed and what those changes mean for existing practices, priorities, feasibility, and implementation plans.

If no significant changes have occurred, the organization does not necessarily need to repeat the entire process.

### Output

- Updated assessment results
- Updated priorities
- Updated feasibility decisions
- Updated implementation roadmap, when warranted

## Module Relationships

The primary process relationship is:

**Existing Practice Identification → Practice Comparison → Organizational-Factor Assessment → Scoring and Priority Ranking → Practice Selection and Feasibility → Implementation Roadmap → Implementation → Evaluation → Reassessment and Adaptation**

The **Assessment Record and Traceability** module supports the assessment, prioritization, feasibility, and reassessment activities by preserving the reasoning and decisions made throughout the process.
